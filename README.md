# Потоковый анализатор файлов

Пакет `streamstats` читает события из CSV и JSONL и создаёт статистический JSON-отчёт.
Файлы обрабатываются последовательно. События выдаются по одному через генераторы,
поэтому все записи файла не сохраняются в список.

**Реализована команда**:

* `analyze`: Прочитать один или несколько файлов, объединить статистику и записать отчёт.

**Дополнительные опции**:

* `--help`: Показать подсказку и выйти.

**Пользование**:

```console
$ python -m streamstats [OPTIONS] COMMAND [ARGS]...
```

**Опции**:

* `--help`: Показать подсказку и выйти.

## `analyze`

Команда подсчитывает:

* Общее число корректных событий.
* Количество событий каждого уровня и каждого источника.
* Top-5 источников по суммарному количеству событий `ERROR` и `CRITICAL`.
* Первую и последнюю временную метку, то есть минимум и максимум времени.
* Количество пропущенных неверных записей.

При передаче нескольких файлов статистика объединяется. Итоговый отчёт
записывается один раз после обработки всех файлов. Все файлы в одном запуске
должны иметь формат, указанный в `--format`.

По умолчанию ошибка события останавливает обработку с кодом 2.
Опция --skip-invalid включает пропуск неверных записей.

**Пользование**:

```console
$ python -m streamstats analyze [OPTIONS] {INPUT}
```

**Аргументы**:

* `INPUT`: Один или несколько входных файлов. Обязательный аргумент.

**Опции**:

* `--format <csv|jsonl>`: Формат всех входных файлов: csv или jsonl. Обязательная опция.
* `--output REPORT file`: Файл JSON-отчёта. По умолчанию REPORT.json.
* `--skip-invalid`: Пропускать неверные записи с WARNING в логе.
* `--help`: Показать подсказку и выйти.

**Вывод**:

JSON-файл по пути `--output`, либо `REPORT.json` в текущей папке.
Если файл отчёта уже существует, он перезаписывается.
Запись отчёта во входной файл запрещена, включая совпадение через другой путь
или ссылку. При таком запуске команда завершается с кодом `2` до чтения данных.
При ошибке события без `--skip-invalid` сообщение с номером файла и строки
выводится в консоль, команда завершается с кодом `2`.
При пропуске записей предупреждения `WARNING` записываются в `logs.log`.

## Входные данные

У каждого события обязательны четыре поля:

| Поле | Значение |
| --- | --- |
| `timestamp` | Время ISO 8601, например `2026-11-03T10:00:00+03:00` или `2026-11-03T07:00:00Z` |
| `level` | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` |
| `source` | Непустая строка, имя источника |
| `message` | Строка; пустое сообщение разрешено |

Файлы читаются в кодировке UTF-8. Поддерживаются русские символы и другие символы Unicode.

**Пример `events.csv`**:

```csv
timestamp,level,source,message
2026-11-03T10:00:00+03:00,INFO,app,Запуск
2026-11-03T10:01:00+03:00,ERROR,database,"Ошибка, соединение потеряно"
2026-11-03T10:02:00+03:00,CRITICAL,database,База недоступна
```

**Пример `events.jsonl`**:

```jsonl
{"timestamp":"2026-11-03T10:00:00+03:00","level":"INFO","source":"app","message":"Запуск"}
{"timestamp":"2026-11-03T10:01:00+03:00","level":"ERROR","source":"database","message":"Ошибка, соединение потеряно"}
{"timestamp":"2026-11-03T10:02:00+03:00","level":"CRITICAL","source":"database","message":"База недоступна"}
```

## Пример отчёта

Для приведённых выше событий:

```json
{
  "total_events": 3,
  "skipped_lines": 0,
  "by_level": {"INFO": 1, "ERROR": 1, "CRITICAL": 1},
  "by_source": {"app": 1, "database": 2},
  "first_timestamp": "2026-11-03T10:00:00+03:00",
  "last_timestamp": "2026-11-03T10:02:00+03:00",
  "top_error_sources": [{"source": "database", "count": 2}]
}
```

# Установка

Должен быть установлен Python >= 3.10 и uv.
Зависимости проекта указаны в `pyproject.toml`, версии зафиксированы в `uv.lock`.

Перейдите в папку скачанного проекта:

```powershell
git clone https://github.com/Gimid934/lab02.git
cd lab02
uv sync
```

## Запуск

Создайте входные файлы, например скопируйте примеры CSV или JSONL выше.
Команды выполняются из корня проекта:

```powershell
uv run python -m streamstats --help
uv run python -m streamstats analyze --help
uv run python -m streamstats analyze events.csv --format csv --output REPORT.json
uv run python -m streamstats analyze events.jsonl --format jsonl --skip-invalid
uv run python -m streamstats analyze first.csv second.csv --format csv --output merged.json
```

## Тесты и проверки

```powershell
uv run python -m pytest
uv run --with ruff ruff check .
uv run --with mypy mypy .
```

Тесты проверяют оба парсера, пустые файлы, повреждённые записи в двух режимах,
Unicode, временные метки, объединение файлов и CLI с временным каталогом.
